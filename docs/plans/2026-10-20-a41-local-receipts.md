# A41 plan: local receipts (7 days OR 500) and offline returns for this tablet's sales

Date 2026-10-20 · base `prod-hardening` c093157 · planner: Opus (read-only), saved by the main session.
Summary: NO migration, NO OpenAPI/generated-type change (`SyncBatchItem.payload` is `additionalProperties: true`; `orders.order_uuid` already UNIQUE). Every task touches SyncEngine / outbox / refunds / journal => Opus review.

## 0. Policy, stated precisely (owner 2026-10-17 item 5)
- Retention: a local receipt is kept while within 7 days of capture OR among the newest 500 local receipts; pruned only when BOTH older than 7 days AND beyond the newest 500. Never prune a receipt whose sale is still in the outbox (queued/retrying/parked) or that is referenced by an unacknowledged refund (queued/parked). "Newest 500" counted over unsynced sales + archived receipts at this terminal's outlet; ranking by `capturedAt`, then `seq`.
- Offline returns for sales made on THIS tablet before it reconnects = YES: (a) a sale still in the outbox, (b) a sale synced from this tablet still in local receipts. Unchanged gates: permission, an open shift with a server id, no queued refund on the same sale, reason 1-500, the A05 12 h lock.

## 1. Where receipts live today (verified)
- Printed receipt = React ref `lastReceipt` (`apps/pos/src/cashier/CashierScreen.tsx:193`, set `:739`), lost on reboot; reprint uses only this ref (`handleReprint` `:756`).
- Unsynced sale = outbox `order` item with full payload (orderNumber, items, paymentMethod, amountPaid, customerId/Name, shiftId, quotedTotal, A10 `receiptSnapshot` which has no customer data `receiptQuote.ts:7-8`), `orderUuid`, `deviceId` (`engine.ts:552-557`), envelope (outletId, userId, shiftId, capturedAt). Stored in the SQLite journal.
- After ack: `applyBatch` settles, `foldAckedRefunds()`, then `outbox.prune()` drops all acked rows (`engine.ts:1110-1114`, `outbox.ts:473`): no durable receipt copy remains; server `ItemResult.orderId` is never stored.
- History: `OrderHistoryPanel.tsx` reads only `GET /orders`; offline fallback `lib/offlineCache.ts` (localStorage). **Bug / A30 leak / unbounded growth:** `orderHistoryQuery.ts:30` key `orders:bd:${from}:${to}:${page}:${term}` creates a never-evicted `mandalika.cache.*` key per search (incl. typed phones/names); cached rows carry `customerName`.
- Refund memory `SyncedRefunds` (`syncedRefunds.ts`): max 500 / 30 days in journal meta key `mandalika.pos.syncedRefunds`, keyed by `payload.orderId` only. Existing pruning: outbox acked rows, SyncedRefunds, A15 settling debits. Nothing for receipts.
- Refunds use server `orders.id` only: `sync.go:467-481` reads `{orderId, reason}`; `RefundTx` (`service/order.go:803`) `WHERE id=$1 AND outlet_id=$2`; `NormalizeRefund` needs a 36-char uuid. `orders.id` is a server default, not the client `orderUuid`, so an unsynced sale cannot be referenced today; `ErrRefundOrderNotFound` is Conflict, non-retryable (`classify.go:41`) -> review. Refunds are whole-order (status flip), so refund > paid cannot happen; `status=='refunded'` -> `ErrAlreadyRefunded` -> review.
- Ordering: POS flushes FIFO by `seq` (`engine.ts:890`); server processes in order and holds only shift_close/shift_open behind an earlier retryable failure.
- Journal meta: native `apply` upserts any meta key, no meta delete (`OutboxJournalPlugin.java:314`); TS `makeKV` allowlists only `JOURNAL_KV_KEY` (`journalOutboxStore.ts:288-329`).

## 2. Design
### 2a. Local receipt book = derived view + archive
- Capture path unchanged (one atomic outbox `apply`). View `LocalReceipts` = unsynced/parked outbox order items ∪ archive entries, filtered to the current terminal outlet with the same `inScope` rule as `pendingStockDeltas`.
- New `packages/sync/src/receiptArchive.ts` (class `ReceiptArchive`, modelled on `SyncedRefunds`: serialized chain, `addMany` resolves only after a durable write, rejects otherwise). One JSON value under `mandalika.pos.receiptArchive` via `store.kv`; journal: add key to `makeKV` allowlist get/set/setDurable (`remove` stays refused: pruning = rewrite the value); KV fallback plain Preferences/localStorage.
- Entry v1 includes: `orderUuid`, `idempotencyKey`, `serverOrderId?`, `orderNumber`, `capturedAt`, `outletId`, `shiftId|null`, `paymentMethod`, `quotedTotal`, `receiptSnapshot` (verbatim A10), `archivedAt`. Excludes: customerName/customerId/phone, notes, salesman* (A30 minimization, Q2). Identity = `orderUuid` only (never `orderNumber`: numbers repeat).
- Server id on ack: extend `OutboxSettle` ack op with optional `orderId`; `settle` stores additive top-level `ackedOrderId` on the item (payload untouched, A11 fingerprint unaffected). Old bundles ignore it.
- Fold before prune (crash-safe): in `applyBatch` `refundsOk = await foldAckedRefunds(...)`, `receiptsOk = await foldAckedReceipts()`; `outbox.prune()` only if both true. If the archive write fails the acked rows stay and the next batch / constructor / `rehydrate()` self-heal (same place as `foldAckedRefunds`, `engine.ts:306`, `:346`) folds again idempotently.
- Pruning runs: on startup (constructor/rehydrate fold) and after every sync batch (the fold); no separate on-save write (a sale adds no archive write; unsynced sales are never prune candidates). Never during a pending write: the archive chain serializes its own writes; the prune decision reads the live `outbox.all()` (unacked refunds' sale keys) inside the chain.
- Size ~1-2 kB/receipt, 500 = ~0.5-1 MB in one value.

### 2b. Offline return flow
- Refund payload must be final when queued (A11). New field `saleOrderUuid` (NOT `orderUuid`: that is the refund item's own uuid added by `commitOutbox`). Unsynced sale: `{orderId: '', saleOrderUuid, reason, orderNumber, total: quotedTotal, paymentMethod, saleShiftId}`. Synced local receipt with known server id: `{orderId: serverOrderId, saleOrderUuid, ...}` (old server ignores `saleOrderUuid`). `orderId` is never filled in later (would be `key_conflict`).
- Client send rule in `engine.flush`, for a refund with `saleOrderUuid`: sale acked (archive or `ackedOrderId`) -> send; sale still queued/retrying -> keep the refund unsent this flush (not a failure) and set `earlierRetryable=true` so shift_close/shift_open stay unsent (A06/M3); sale parked for review -> park the refund too, client code `sale_in_review` (never deleted; text says do not pay again; parking, not holding, so shift close is not blocked forever); sale unknown -> send, server decides.
- Double-refund gates (UI; server is authority): `queuedRefundOrderIds()` gains sibling `queuedRefundSaleUuids()`; `foldAckedRefunds` records `payload.orderId`, `payload.saleOrderUuid` and the result's server `orderId` in `SyncedRefunds` (plain strings, no storage change); `refundAvailability` matches on either id using the archive's uuid<->server id map.
- Unchanged: refund gate requires a shift with a server id (Q1); no optimistic stock credit. Recap: `refundRecap.ts` already handles `orderId ''` / own-shift / cross-shift (needs tests only).
- Reprint from a local receipt: `receiptSnapshot` through `receiptFromQuote` with REPRINT flag; never through `saleGate`, never enqueues; customer name omitted (Q2); cashier name "-". `handleReprint` falls back to the newest local receipt when `lastReceipt` is empty after a reboot.

## 3. Server (no migration, no OpenAPI)
`backend/internal/sync/sync.go` refund case (~452-486): payload struct gains `SaleOrderUUID string json:"saleOrderUuid"` and `DeviceID string json:"deviceId"`. Inside the `keyed` effect (receipt + effect one transaction): if `OrderID==""` and `SaleOrderUUID!=""`: `SELECT id, device_id FROM orders WHERE order_uuid=$1 AND outlet_id=$2`; no row -> `ErrRefundOrderNotFound` (Conflict -> review; not retryable); `device_id` != payload `deviceId` -> Conflict review (enforces "THAT tablet" on the uuid path only); both ids sent but not the same row -> Rejected (review); `saleOrderUuid` must be a canonical 36-char uuid (reuse `NormalizeRefund` rule); receipt outcome returns the resolved server id so a replay returns the same `orderId`. `RefundTx` unchanged (gets resolved id): double-refund, not-completed, outlet scope, A42 lock order, permission, A05 `offline_expired`, A11 replay all still apply. A05: a sale captured >12 h offline gets `offline_expired` -> client parks the refund (`sale_in_review`). A10: refund display uses `quotedTotal`; existing behaviour on `quote_warning`.
