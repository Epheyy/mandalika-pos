## Tasks

### T1 — Points redemption parity (Go + TS, shared golden vectors)
- New `backend/internal/service/testdata/points_redemption_golden.json`: cases `{name, requested, available, rate, total, expected:{points, amount}}`.
  Include: integer rate normal; integer rate capped by total (e.g. total 95550, rate 100); total below one point (total 50, rate 100, req 1 →
  points 0, amount 50 — today's A22 behaviour, documented as such); fractional rates (1.5, 0.3, 2.5, 0.1) incl. half-rupiah rounding;
  requested > available; available 0.
- Go: one pure helper (e.g. `RedeemPoints(requested, available int, rate, total float64) (points int, amount float64)` in `service`),
  with EXACTLY the POS arithmetic: `p = min(requested, available)`, `amount = min(math.Round(p*rate), total)`,
  `points = min(p, int(math.Floor(amount/rate)))`. Use it in `order.go` in place of the inline block; keep the NaN/Inf/negative guard,
  the void-replacement `available` cap and the `points_shortfall` note exactly as they are.
- TS: extract the same arithmetic in `pricing.ts` into an exported helper used by `computePricing` (no behaviour change).
- Tests: Go golden test + TS test both reading the same JSON (pattern: `promo_parity_golden_test.go` / `promoParity.test.ts`); pin the case count.
  Existing order/loyalty tests must stay green unchanged.
