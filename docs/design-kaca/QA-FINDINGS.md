# QA findings: Mandalika Back Office (live UI/UX test run)

Tested: https://mandalika-pos.pages.dev/ (test data), Chrome desktop, viewport ~1536×674, logged in as Administrator.
Date: 4 Nov 2026. Method: walked every page in the sidebar, opened forms/dialogs, triggered validation, and ran
create/edit/delete/approve flows on test data.

Severity: **P1** = wrong data, data loss or a broken page · **P2** = misleading/confusing, fix soon · **P3** = polish.
These are in addition to the visual glass redesign; fix P1/P2 while restyling, since the same components are touched.

## Coverage
Tested: Login, Ringkasan, Laporan (Transaksi, Ekspor, Shift, Hadiah Promo, Kode Diskon, Refund, Stok Minus),
Pelanggan (Daftar, Pengingat, Duplikat, Loyalitas + add/edit/delete), Promosi (add/deactivate/undo/delete, Kode Diskon list),
Produk (list, add form + validation, leave guard), Inventori (Stok Produk, Transfer detail + send + receive, Barang Masuk,
Bahan, Opname list), Persetujuan Stok, Permintaan Barang, Pengguna (list, add form opened only), Tinjauan Sinkron,
Pengaturan (Outlet & Gudang, Transaksi + save bar + leave guard), Integrasi ERP.

Round 2 added: Log Kesalahan, backoffice at phone width (~500 px), and the **cashier POS** (localhost:5173) at tablet
landscape (1282×667), tablet portrait (802×667), phone portrait (502×667, Chrome's minimum window width) and phone landscape
(844×391), including a full cash sale. Heights are capped by the test laptop's screen (816 px), so 1280×800 itself could not be
reproduced exactly; widths match the real breakpoints.

Round 3 added: Manajemen Role, Produk Kategori/Bundle, Kode Diskon create, Kartu Stok / Pergerakan, Pengaturan Operasional and
Resep & Bahan, keyboard pass (backoffice); POS customer lookup, promo code, manual discount, refund, Koneksi & antrean, Tutup Shift
and Buka Shift.

**Not yet tested:** opname run; Bahan sub-tabs (Daftar, Penyesuaian, Transfer); true offline mode (needs the network cut);
a real Galaxy Tab A9. No user accounts were created (out of scope for an automated run).

## P3: inconsistencies to fix in the redesign
- **Form containers:** Pelanggan/Pengguna use a centred modal, Promosi/Produk a slide-over, Transfer Terima a large modal. Standardize: slide-over for create/edit, dialog only for confirm.
- **Validation:** three styles (hidden message / disabled save / summary + field errors). Standardize on Produk's (summary + field errors + "Perubahan belum disimpan").
- **Confirm dialogs:** two designs (icon-centred full-width buttons + bright red `#e00` vs left-aligned, named item, darker red). Use one ConfirmDialog (Kit D1) that always names the item, with the danger token.
- **Selected state:** solid gold chips, pale gold chips (Pengingat), white selector thumb, underlined tabs (Bahan). Use the glass rules: selector = white thumb, choice = `#8f6412` fill.
- **Tabs:** placement varies (right of title; above title in Inventori; left segmented in Tinjauan Sinkron) and up to three nested levels (Inventori › Stok Produk › Ikhtisar › Outlet). Tab bar shifts width when the selection changes (Laporan). Tabs lack `role="tab"`/`aria-selected`.
- **Control heights:** chips ~30 px next to selects ~38 px and buttons 34–40 px in the same row (Pelanggan, Kode Diskon header).
- **Labels:** filter labels are uppercase on some pages, sentence case on others, missing on others; one select labeled and its neighbours not (Promosi "Jenis").
- **Wording:** "Export" / "Ekspor" / "Unduh"; "Import", "Manajemen Role", "Buy 1 Get 1" (table says "Beli-Gratis"), "poin ON"; save button "Simpan" vs "Tambah".
- **Breadcrumbs** repeat: "Pelanggan › Pelanggan", "Produk › Produk", "Promosi › Promosi", "Pengguna › Pengguna"; Transfer detail doesn't show its number.
- **Default date ranges** differ (Laporan Transaksi 30 days, other report tabs today).
- **Time formats:** "13:59" vs "10.35"; order numbers sometimes monospace (Stok Minus, Transfer), sometimes not.
- **Empty states:** three styles (light small "Belum ada data", bold grey with icon, centred vs top-aligned). An empty search says "Tidak ada pelanggan" instead of "Tidak ada yang cocok dengan 'Uji'".
- **Status colours:** "Dibatalkan" in red (Kit D1 says neutral); "Bisa Kombinasi" and category tags gold-tinted (gold is for actions/selection only); refund amount in bright red `#e00` instead of the danger token; "Status per item" in a warn box though it's information.
- **Primary actions:** Transfer detail shows two gold buttons (Terima + Bagikan) plus a solid red Batalkan of equal weight.
- **Status shown twice:** Promosi rows show a switch *and* an "Aktif" tag.

## P3: layout
- (Moved to P2 #35.) Scroll areas inside the scrolling page.
- Layout jumps when the page scrollbar appears/disappears (search results); use `scrollbar-gutter: stable`.
- Search placeholders cut off: "Cari nama / telepon / em…", "Nama, brand, SKU atau barcod…".
- Ringkasan: top/bottom product cards stretch to the Barang Habis height with "Belum ada penjualan" at the top; payment donut uses only gold shades (slices indistinguishable).
- Laporan Transaksi: the Export button wraps alone to a second row at ~1400 px.
- Sidebar logo image renders tiny and illegible next to "Mandalika".
- Pelanggan table column widths change after filtering (auto table layout).
- Breadcrumb stays "Stok Produk" on the Pergerakan / Kartu Stok sub-tabs; an invalid sub-route (e.g. `#/pengaturan/resep`) silently shows the first tab.
- Cancel buttons are labelled "Batal" in most dialogs but "Kembali" in the opname cancel dialog.
- Produk › Bundle is "read-only" (English) while Promosi has its own "Paket Bundel" type: two bundle concepts.

## P3: accessibility
- Icon-only buttons (edit, delete, copy, key) have no accessible name.
- Login: button text white 14 px on `#b07d18` ≈ 3.6:1 (fails AA); placeholder-only labels; email `type="text"`; no "Lupa kata sandi".
- Report tabs and sub-tabs are plain buttons without tab semantics.
- Keyboard focus is visible (gold outline) but there's no "Lewati ke konten" skip link, so every page starts by tabbing through the whole sidebar.
